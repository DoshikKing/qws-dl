# Dependency security notes

Reviewed on 2026-10-23.

The pinned OrpheusDL and Qobuz module are adapted at worker startup by
`scripts/worker_safety.py` and `scripts/qobuz_web.py`. Do not launch the upstream
CLI directly as a substitute for `scripts/run-orpheus.py`: direct invocation does
not apply the application's TLS, path, budget or pagination boundaries.

`protobuf==3.15.8` was unused by the pinned Qobuz workflow and has been removed
from `requirements-orpheus.lock`. Existing local virtual environments should run
`python -m pip uninstall protobuf`; new container builds do not install it.

## Outstanding build/development dependency

`node-forge@1.4.0`, pulled in by Nuxt's `nitropack -> listhen` tooling, is affected
by [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv).
At review time 1.4.0 remains the latest npm release; `npm audit` has no available
fix. Its seven reported High entries are one advisory propagated through the graph.
No suppression or unsafe dependency override is applied.

The Node production artifact generated by `npm run build` does not package
`node-forge` or `listhen`. The Docker runtime copies that artifact rather than the
build-stage `node_modules`. Regression HTTP tests verify the artifact boundary.
Run production through `npm start` or the supplied Dockerfile, behind your TLS
reverse proxy. Development tooling is not a public production listener.

Recheck `npm audit` when updating Nuxt/Nitro/listhen or when a patched forge release
becomes available. Artifact isolation reduces production exposure; it does not
make the installed development dependency itself patched.
