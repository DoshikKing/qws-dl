# Настройка и эксплуатация QWS

[Основной README и дисклеймер](README.md) · [Русский README](README.ru.md) · [English documentation](INFO.md)

Веб-интерфейс на Nuxt 4 для OrpheusDL с установленным модулем Qobuz.
Ссылки на треки, альбомы, плейлисты и исполнителей → очередь → файлы на сервере.
Есть выбор качества, журнал, отмена заданий, библиотека с поиском и скачиванием файлов.

## Docker Compose

```sh
cp .env.example .env
# Заполните WEB_PASSWORD, QOBUZ_USERNAME и QOBUZ_PASSWORD в .env.
docker compose up -d --build
docker compose logs -f
```

Откройте `http://localhost:3000` и войдите с паролем `WEB_PASSWORD`.
OrpheusDL и Qobuz устанавливаются автоматически при сборке образа; вручную клонировать их не нужно.
Контейнер работает от непривилегированного пользователя. Внутри — Python, FFmpeg и Node.js.

Для сети с собственным доверенным CA поддерживается BuildKit secret:
`docker build --secret id=build_ca,src=/path/to/organization-ca.pem -t qws-dl .`.
CA добавляется в хранилище доверия; проверки TLS и подписей пакетов остаются включёнными.

Файлы сохраняются в том `downloads`, история и сессия Qobuz — в `app-data`.
`docker compose down` сохраняет тома; **`docker compose down -v` удаляет коллекцию и настройки**.
Чтобы скопировать коллекцию: `docker compose cp qws-dl:/downloads ./saved-downloads`.
После изменения `.env`: `docker compose up -d --force-recreate`.
По умолчанию порт доступен только на localhost. Для удалённого доступа настройте TLS reverse proxy;
`WEB_BIND` определяет адрес привязки, `WEB_PORT` — порт на хосте. Не запускайте несколько реплик на общих томах.

## Локальная разработка

### Подпуть nginx `/dl/`

Блоки `location` для существующего `server {}` находятся в [deploy/nginx-dl.conf](deploy/nginx-dl.conf).
Добавьте `NUXT_APP_BASE_URL=/dl/` в `.env` и пересоберите приложение после обновления кода:
`docker compose up -d --build`. Конфиг предполагает nginx на хосте и приложение на `127.0.0.1:3000`.
В `proxy_pass` нет завершающего `/`: приложение должно получать полный путь `/dl/...`.
Если nginx работает в общей Docker-сети, замените upstream на `http://qws-dl:3000`.
Проверьте конфигурацию командой `nginx -t`, затем перезагрузите nginx.
Префикс применяется также к API, ресурсам, ссылкам и cookie; `/api/health` становится `/dl/api/health`.
Поддерживаются `/`, `/dl`, `/dl/` и вложенные пути вроде `/music/dl/`.
`NUXT_APP_BASE_URL` — путь внутри сайта, например `/dl/`, а не полный адрес с доменом.
После первого обновления кода изменение только этого параметра не требует пересборки:
`docker compose up -d --force-recreate`. При запуске без Docker перезапустите `npm start` или `npm run dev`.

### Запуск без Docker

Нужны Node.js 22.12+ (или 24), Python 3.10+ с `venv`, Git и FFmpeg в `PATH`.
На Debian/Ubuntu: `apt-get install python3 python3-venv git ffmpeg`.

```sh
npm ci
npm run setup:orpheus
cp .env.example .env
# Заполните .env.
npm run dev
```

Nuxt читает `.env` в режиме разработки. Production:

```sh
npm run build
npm start
```

`npm start` загружает `.env` средствами Node.js. При прямом вызове `.output/server/index.mjs`
переменные должен передать процесс запуска. В Compose их передаёт `env_file`.
`npm run setup:orpheus` можно запускать повторно; изменённые отслеживаемые файлы upstream он не перезаписывает.
Python-зависимости закреплены в `requirements-orpheus.lock`, JavaScript-зависимости — в `package-lock.json`.

## Настройки `.env`

| Переменная                          | Назначение                                                                                                                               |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `WEB_PASSWORD`                      | Обязательный длинный пароль веб-интерфейса; без него API закрыт                                                                          |
| `QOBUZ_USERNAME`, `QOBUZ_PASSWORD`  | Учётная запись Qobuz с доступом к загрузкам                                                                                              |
| `QOBUZ_AUTH_MODE`                   | `web` по умолчанию: вход по email/паролю, параметры веб-клиента автоматически. `token`: ваша браузерная сессия; `mobile`: прежний модуль |
| `QOBUZ_USER_ID`, `QOBUZ_AUTH_TOKEN` | ID своего аккаунта и токен собственной браузерной сессии; только для режима `token`                                                      |
| `QOBUZ_APP_ID`, `QOBUZ_APP_SECRET`  | Только для `QOBUZ_AUTH_MODE=mobile`; согласованная пара мобильного приложения                                                            |
| `DOWNLOAD_RETENTION_HOURS`          | Срок хранения по умолчанию после завершения: целое число от 1 до 24 часов, по умолчанию 24                                               |
| `DOWNLOAD_QUALITY`                  | `hifi` (до 192 кГц / 24 бит), `lossless` (44,1 кГц / 16 бит), `high` (MP3 320)                                                           |
| `ORPHEUS_DIR`, `PYTHON_BIN`         | Путь к установленному OrpheusDL и Python его виртуального окружения                                                                      |
| `DATA_DIR`, `DOWNLOAD_DIR`          | Каталоги истории и загруженных файлов                                                                                                    |
| `JOB_TIMEOUT_SECONDS`               | Лимит времени одного задания, по умолчанию 7200 секунд                                                                                   |
| `WEB_BIND`, `WEB_PORT`              | Только Compose: адрес и порт на хосте                                                                                                    |
| `NUXT_APP_BASE_URL`                 | Базовый путь приложения: `/` по умолчанию, например `/dl/`                                                                               |

Относительные локальные пути считаются от корня проекта. В Compose пути переопределены на контейнерные.
Секреты не передаются в браузер и не включаются в Docker-образ. При загрузке Python записывает их в
конфигурацию OrpheusDL с правами 600; том `app-data` и локальный `.runtime` содержат приватные данные.
Журналы ограничены по размеру, URL и значения секретов скрываются. Не публикуйте `.env` и тома.
Статус «Настроено» проверяет наличие параметров, а не успешную авторизацию в Qobuz.
В режиме `web` приложение получает параметры веб-клиента автоматически через `qobuz-dl`.
`QOBUZ_APP_ID` и `QOBUZ_APP_SECRET` в этом режиме игнорируются, в том числе оставшиеся от старой настройки.
Используйте сервис для контента, к которому у вас есть разрешённый доступ.

## Очередь и ограничения

Один Python-процесс обслуживает очередь по порядку, чтобы не повредить сессию OrpheusDL.
Отмена останавливает группу процессов; уже сохранённые файлы остаются в библиотеке.
После перезапуска ожидающие задания продолжаются, прерванное задание получает статус ошибки:
при необходимости добавьте его ссылку заново. История хранит последние 200 записей и все задания с ещё не истёкшим сроком хранения, очередь — до 50 активных.
Каждое задание пишет в собственный каталог. Библиотека показывает до 1000 файлов; полная коллекция остаётся на диске.
Успешное задание означает завершение CLI без ошибок, обнаруженных в выводе;
OrpheusDL управляет метаданными, доступностью треков и выбором фактического качества.
Отдельные ошибки треков считаются ошибкой задания, даже если upstream возвращает код 0.
Поиска по каталогу нет: этот модуль объявляет режим загрузок, а не поиска в OrpheusDL.

## Проверки

```sh
npm test
npm run test:python
npm run typecheck
npm run build
docker compose config --quiet
```

После сборки и установки Python-окружения: `npm run test:integration`.
Этот тест запускает production-сервер и проверяет вход, очередь, Python-мост, выдачу файлов,
ошибку отдельного трека, отмену и восстановление истории. Вместо сетевого Qobuz используется локальный стенд.

На момент проверки `npm audit` сообщает 11 high в цепочках инструментов сборки (`braces`, `node-forge`).
`npm audit fix` их не устраняет в текущих upstream-версиях. Эти пакеты отсутствуют в собранном
production-сервере `.output`; для развёртывания используйте production-образ, а не dev-сервер.

`/api/health` проверяет HTTP-сервер, не Qobuz. Проверка реальной загрузки:
заполните учётные данные, добавьте доступный вашему аккаунту трек, дождитесь завершения,
откройте библиотеку и скачайте файл. Без действительных данных Qobuz эту проверку выполнить нельзя.

Upstream закреплены на коммитах в `scripts/install-orpheus.sh`:
[OrpheusDL](https://github.com/OrfiTeam/OrpheusDL) и
[OrpheusDL Qobuz](https://github.com/yarrm80s/orpheusdl-qobuz).
Исходники upstream не включены в этот репозиторий, устанавливаются в `.runtime` или `/opt/runtime`.

## Вход в Qobuz без ручных app_id / app_secret

В режиме по умолчанию нужны только:

```dotenv
QOBUZ_AUTH_MODE=web
QOBUZ_USERNAME=your-email@example.com
QOBUZ_PASSWORD='your-original-password'
```

Нужен обычный пароль аккаунта Qobuz, не хеш и не пароль Google/Apple.
Одинарные кавычки сохраняют `$` и `#` в `.env` Docker Compose.
Приложение получает параметры веб-плеера, входит в Qobuz и проверяет доступ к загрузкам;
OrpheusDL продолжает загружать файлы, обложки и теги. Старый сохранённый мобильный токен
не используется для веб-входа. Удалять тома или историю при переходе не нужно.

Обновление существующей установки:

```sh
git pull origin main
docker compose up -d --build
```

Если раньше в `.env` были `QOBUZ_APP_ID` / `QOBUZ_APP_SECRET`, можно их удалить.
Действительные собственные мобильные параметры по-прежнему поддерживаются при явном
`QOBUZ_AUTH_MODE=mobile`.

Для веб-входа серверу нужны HTTPS-доступ к `play.qobuz.com` (страница входа и bundle)
и `www.qobuz.com` (API), затем к адресам файлов и обложек, возвращённым Qobuz.
Параметры веб-клиента не отправляются в браузер и не включаются в репозиторий.
Изменение формата веб-плеера может потребовать обновления интеграции; приложение
сообщает отдельно об отказе входа 401, отсутствии подписки, сетевой ошибке и ошибке разбора плеера.

Используется [qobuz-dl 0.9.9.10](https://github.com/vitiko98/qobuz-dl) (GPL-3.0),
устанавливаемый как Python-зависимость. Его код и лицензия сохраняются в окружении Python;
исходники сторонней библиотеки в этот репозиторий не копируются.
`npm run test:python` проверяет реальные библиотеки авторизации и модуль OrpheusDL
на локальных ответах HTTP: получение параметров, вход, выбор корректной подписи,
метаданные, отказ 401 и отсутствие подписки. Это не проверка вашего аккаунта в живом сервисе.

## Названия загрузок

В очереди и имени ZIP показываются исполнитель и название из метаданных OrpheusDL.
Название появляется после получения метаданных; до этого видны тип материала и ID Qobuz.
Новые аудиофайлы называются «Исполнитель - Название», внутри альбомов и плейлистов — с номером трека.
Кириллица в именах ZIP сохраняется. Существующие файлы не переименовываются; для старых
заданий название берётся из папки альбома или имени единственного аудиофайла, если это возможно.

## ZIP-архивы и срок хранения

На форме загрузки выберите срок от 1 до 24 часов. По умолчанию он задаётся
через `DOWNLOAD_RETENTION_HOURS=24`. Отсчёт начинается после завершения задания,
в том числе ошибки или отмены, если остались частичные файлы.

Кнопка ZIP появляется в очереди и библиотеке после остановки загрузчика.
Архив содержит все файлы задания с исходной структурой папок. Он создаётся по запросу,
кэшируется в папке задания и поддерживает ZIP64 для больших файлов.
Аудио не пережимается, символические ссылки игнорируются; архив не включает сам себя.
Кэш ZIP может временно удвоить место, занимаемое заданием на диске.

По окончании срока сервер удаляет папку задания вместе с файлами и ZIP.
Новые запросы к просроченным файлам блокируются; запись в истории сохраняется.
В интерфейсе отображаются время истечения и отметка удаления.
Если удалить файлы не удаётся, интерфейс показывает ошибку прав доступа,
сервер повторяет попытку, а выдача просроченных файлов остаётся заблокированной.

Очистка выполняется работающим сервером и при запуске. Если сервер выключен,
просроченные файлы удаляются при следующем старте; для удаления по расписанию
сервер должен работать. Старым записям назначается срок 24 часа от времени завершения.
Конфигурация и посторонние каталоги, вручную помещённые в downloads, не удаляются.

## В браузере вход работает, а приложение получает 401

Обновите приложение: адаптер теперь отправляет POST-форму, а не устаревший GET-запрос библиотеки.
Сам по себе ответ 401 не доказывает, что пароль неверный.
Если Qobuz продолжает отклонять парольный вход, используйте **свою действующую браузерную сессию**:

```dotenv
QOBUZ_AUTH_MODE=token
QOBUZ_USER_ID=ID_вашего_аккаунта
QOBUZ_AUTH_TOKEN='токен_вашей_сессии'
```

1. Войдите в свой аккаунт на `play.qobuz.com`.
2. Откройте инструменты разработчика → Network → Fetch/XHR и обновите страницу.
3. Найдите запрос Qobuz `user/login` или `user/get`. В ответе посмотрите `user.id`
   (либо `id` для `user/get`) и `user_auth_token`. Токен также может быть в заголовке запроса
   `X-User-Auth-Token`.
4. Сохраните значения только в своём `.env`. После обновления кода выполните
   `docker compose up -d --build`. Для последующей замены только токена достаточно
   `docker compose up -d --force-recreate`.

В режиме token логин/пароль и ручные ключи приложения не нужны. Параметры веб-клиента
по-прежнему получаются автоматически; необходим подходящий аккаунт с доступом к загрузкам.
Токен — секрет: не присылайте его в чат, скриншотах, HAR, логах и не коммитьте.
Приватная конфигурация Orpheus хранится с ограниченными правами.
Если сессия истечёт, обновите токен из своего браузера.

### Проверить передачу пароля в контейнер

Если свежий вход на сайте работает, проверьте, совпадает ли пароль внутри контейнера
с введённым вами. Команда запрашивает его локально без отображения и выводит только результат:

```sh
docker compose exec qws-dl /opt/runtime/venv/bin/python -c 'import getpass,hmac,os; p=getpass.getpass("Qobuz password: "); v=os.environ.get("QOBUZ_PASSWORD", ""); print("MATCH" if v and hmac.compare_digest(p.encode(),v.encode()) else "DIFFERENT")'
```

При `DIFFERENT` проверьте `.env`, кавычки и пересоздайте контейнер. В режиме token эта проверка не нужна.
